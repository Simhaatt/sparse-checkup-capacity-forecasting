# Code provenance

The study was run in four stages. Each stage ran in its own workspace. The scripts in `experiments/` are the files that were executed. `code_provenance.csv` lists every file with its SHA-256 hash and status:

- `verbatim`: the same bytes as the run copy, after line endings are normalised;
- `paths edited`: see below;
- `added for this repository`.

| Folder | Manuscript name | Where it ran |
|---|---|---|
| `stage0_capacity_retuning` | earlier capacity-only experiments: Chronos zero-shot, Oxford preparation, semi-empirical controls | Windows laptop |
| `stage1_initial_benchmark` | "initial grouped benchmark": 20 configurations per family per fold, selected at origin 20 | Windows 11 laptop, Python 3.14.3 |
| `stage2_sandia` | "independent benchmark" | Linux, 2 CPUs, Python 3.13.16 |
| `stage3_main_study` | main study: residual learner, re-tuning, transfer, ablations, intervals, decisions, robustness | Linux, 2 CPUs, Python 3.13.16 |

Internally the stages were called "round 3" (stage 1) and "round 4" (stage 3). That is why file names start with `r3`/`r4` and the plan file is `PLAN_R4.json`. Plan codes such as R4A–R4G and G7 are the arms and time-stamped amendments recorded in that file.

## Edits made for the public repository

The runs used absolute paths on their machines:

- `/home/claude/r4` and `/home/claude/sandia/bench` in the Linux workspaces;
- `C:\Users\...` in a few Windows report templates.

The following edits were made, and every edited line carries the comment `# repo edit`:

- In `stage3_main_study/*.py`, the Sandia benchmark folder is now `$SNL_BENCH`, which defaults to `experiments/stage2_sandia`.
- In `stage3_main_study/*.sh` and `stage2_sandia/run_all.sh`, `cd /home/claude/...` was replaced by `cd "$(dirname "$0")"`.
- In `paper_figures/scripts/prepare_plot_data.py`, the default `--r4` folder is now the repository's main-study folder.

`repo_edits.diff` shows every changed line; nothing other than paths was changed. Windows paths that appear inside the text of report templates in `stage1_initial_benchmark` and in `leakage_audit/audit_raw_resistance.py` were left unchanged. They need adjusting before those scripts are re-run.

`stage3_main_study/r3.py`, `univariate.py` and `trainer/exp_lib.py` are byte-identical copies of the stage-1 files. The main study imported them.

## Added files

- `stage3_main_study/summarise_from_predictions.py` re-implements the summary blocks that follow model training in `r4_transfer.py`, `r4_uncert.py`, `r4_g.py` (g1, g4) and `r4_ablate.py`. It also regenerates the post hoc tables that were produced interactively: horizon, regime and post hoc pairs. It reproduces every deposited table exactly (`reproduce/level1.py`).
- `reproduce/level1.py`, `reproduce/expected_values.json` and `scripts/setup_workspace.py`.

## Prediction files

- `r3_reference_predictions.csv.gz` is the consolidated stage-1 output used by the main study.
- In mixed-dataset files, the Sandia rows were removed: `r4_g3_noschedule_pred_luh`, `r4_pooled_pred_luh`. The reason is in `DATA_LICENSE.md`.
- Pickled ARIMA caches were not deposited. They are regenerated by `r4_ablate.py arima_cache`.
